# 0. 文档目的与确认范围

本文定义基于 `loudon84/anything-llm` 的企业应用二开需求。2026-10-14 根据需求 grilling 的用户确认，重新收敛首期范围；覆盖原 v1.0 中与本轮决定不一致的首期要求。

首期目标：员工能够基于选定会议的摘要、转写、附件及补充资料查询既有业务规定，并追溯答案来源；可显式选择已有 AnythingLLM Workspace 作为额外知识源。

业务主流程：

    企业统一配置腾讯会议 API
      → 获取会议列表 → 用户逐场选择并确认导入范围
      → 持久化后台导入 → 草稿会议
      → 有内容则解析和索引；仅元数据则等待人工补资料并完成索引
      → 单场／多场知识问答 → 引用定位与证据核查
      → 条件不明则澄清；证据不足则资料待补充
      → 补充资料到指定会议 → 用户手动重新回答

本项目不重新实现音视频采集、ASR 或基础会议摘要。腾讯会议提供原始会议产物；系统负责获取、管理、解析和检索。允许用户修订摘要和转写，不要求系统重新生成基础摘要。

文档中的需求为交付及验收约定，不表示对应能力已经实现或接口已经验证。腾讯会议 API 可用性、解析质量、问答质量和并发性能必须通过实际验证确认。

# 1. 产品定义与首期边界

## 1.1 产品定位

AnythingLLM Enterprise Meeting Intelligence：以会议知识检索为首期核心的企业 AI 工作空间扩展。

## 1.2 首期包含

- 企业统一腾讯会议官方 API 连接及会议列表查询。
- 逐场手动导入，导入范围确认、超限缩减及后台处理。
- 会议摘要、转写、附件及补充资料的展示、解析和索引。
- 草稿／核准、摘要和转写修订、草稿删除及历史留存。
- 单场及最多 10 场跨会议问答，可跨季度选择。
- 显式选择已有 Workspace 联合检索。
- 引用定位、引用片段快照、回答历史版本、来源变更提示。
- 资料待补充记录、文件／文本补充和手动重新回答。

## 1.3 首期不包含及后续事项

- 文档比较、文档翻译、OA 任务创建全部延期，不作为首期发布条件。
- 不新建独立企业文档中心或企业知识库管理模块；企业知识库复用已有 Workspace。
- 不提供自动导入、批量导入、已导入会议的腾讯侧内容更新或自动补取。
- 不做摘要、转写或补充文本的全文版本管理。
- 不要求图表趋势、流程图关系理解或 Excel 公式重算。
- 不查询实时运价、快递时效、外部报关资料或其他外部知识源。
- 会议权限本轮不展开，不列为首期专门验收条件；后续通过会议接口过滤补充。此前讨论的导入时指定访问范围暂不纳入首期。
- 不要求旧实例数据迁移，不新增多种部署方式的兼容验收要求。

# 2. 业务场景与回答边界

## 2.1 首期真实业务场景

使用供应链仓库会议作为业务验收材料：

1. 会议如何确定库存拣货、出货确认的追溯过程？回答资料中规定的步骤、责任人、记录及凭证。
2. 海外货运中，仓库人员如何确认付运方式，并根据送达日期、货运成本选择快递公司？查询已有流程、条件及已形成的结论，不进行实时公司推荐或运价查询。
3. 下快递单前，如何要求寄送方提交报关资料确认？需要向快递公司收回哪些凭证？查询提交、确认、允许下单的条件及凭证要求。

未在资料中确定的环节不能补写成业务规定。

## 2.2 证据规则

- 禁止用模型自身知识补充业务事实、操作要求、凭证清单或结论。
- 回答仅使用当前对话选定会议及显式选择的 Workspace 资料；每个业务结论需具备可追溯来源。
- 区分建议、讨论意见与明确通过的决定。未找到通过证据时，不得把建议表述为必须执行的规定。
- 核准仅表示资料完整、可读，不表示其中每项建议均获业务批准。
- 会议之间、会议与企业知识库之间出现冲突时，列出各自说法、日期及引用，不按新旧顺序或知识库身份自动裁决。
- 资料表明存在不同仓库、目的地、货物类型等适用流程，而用户未说明关键条件时，先询问适用条件，标记待用户澄清。澄清条件须来自资料，不由模型自行添加。
- 条件已明确但缺少回答证据时，说明缺失信息，询问用户是否补充知识源，记录为资料待补充。已有证据支持的部分可回答，缺失部分不得给出确定结论。
- 服务异常、文件解析失败、检索不可用不属于资料待补充，必须报告处理失败。
- 采用尽力检索，不保证穷尽全部决定或行动项。对于“所有／全部”等问题，明确是检索到的相关内容，不暗示完整覆盖。

# 3. 总体结构与集成原则

    AnythingLLM Enterprise
    ├── Meeting Center
    │   ├── Tencent Meeting API Connector
    │   ├── Meeting List / Import Scope Selection
    │   ├── Background Import Jobs
    │   ├── Summary / Transcript / Attachments
    │   ├── Review / Delete / Supplement
    │   └── Meeting Retrieval and Citation
    ├── Existing AI Workspace
    │   └── 用户显式选择的 Workspace 知识源
    └── Meeting QA
        ├── 固定会议与 Workspace 范围
        ├── 回答与引用快照
        └── 待补充问题 / 回答历史 / 手动重新回答

每场会议具备独立详情和资料归属，但不强制为每场会议创建一个 AnythingLLM Workspace。实现方式须同时满足单场、跨会议及已有 Workspace 联合检索。

模块划分为实施建议，不代表已核查当前仓库中的目录或扩展接口。实施时复用已有连接、文件处理、模型配置和检索能力；缺失能力按本 PRD 补充。

# 4. 规模、归档与部署约束

- Linux 为首期交付和验收环境，允许直接访问所需外部服务。Docker／源码启动的具体交付方式未指定。
- 采用全新部署验收，不要求迁移旧用户、Workspace、文档和聊天记录；验收知识库在新实例准备。
- 按会议开始时间所属季度归档，历史季度长期保留，允许跨季度选会。
- 每季度最多 200 场当前未删除的会议，包括仅元数据、等待补资料的草稿；失败任务、历史记录不占正式会议名额。删除释放名额，重新成功导入重新计入。
- 并发导入需采用名额预留或等效并发控制，确保成功导入后的季度数量不超过 200；失败释放临时预留。
- 单次跨会议问答最多选择 10 场。
- 单场转写导入时长上限 3 小时。源会议超过 3 小时可选择时间段，所选累计时长不得超过上限。
- 单个附件最大 100 MB；每场最多 20 个附件，总计不超过 500 MB。腾讯原始附件和用户补充文件分区展示，但限额合并计算。已删除并留档的补充文件不占当前附件名额；重新上传按新增文件校验数量、大小及唯一性。
- 源端超过附件数量、大小或转写时长限制时，允许选择部分内容导入，不静默截断或丢弃。
- 约 10 人同时提问作为并发测试场景。开始显示回答及完整回答的耗时、失败率先实测，发布前确定门槛；当前不承诺具体秒数。

# 5. 功能需求

## REQ-MEETING-001 企业统一腾讯会议 API 连接

管理员配置企业统一连接，按腾讯会议官方 API 标准对接，不实现 MCP。当前已有账户或凭证，但尚未验证实际接口能力。

必须支持连接配置、会议列表获取及用户逐场选择。待验证能力包括列表分页、可访问会议范围、摘要、转写、源端附件获取与下载、产物延迟、限流和失败重试。

会议列表获取和真实 API 连接是首期必需能力。某类内容经验证无法由官方 API 提供时，允许人工上传或填写补齐，并标明来源和缺失项；接口本应可获取但调用失败时，不得以能力缺失为由跳过。

页面及流程可先基于约定数据结构和模拟数据实施，其他人员并行验证腾讯会议 API。模拟联调通过不等于真实接入验收通过。

验收：使用实际企业连接获取会议列表，并以真实可用会议验证内容获取；保留能力验证清单和不可用项的人工补齐路径，不虚构已验证的接口端点。

## REQ-MEETING-002 逐场手动导入与范围确认

- 用户一次选择一场会议，确认摘要、转写时间段及附件范围后创建后台任务，不支持批量或自动导入。
- 对源端不存在的转写／附件、API 能力不可获取、可获取但调用失败分别展示原因。
- 只有摘要、没有转写的会议允许导入及问答，明确展示“仅摘要可用”。
- 若元数据获取成功，但摘要、转写及附件均因源端不存在或经验证的接口能力限制而不可获取，允许先创建仅元数据的草稿。导入任务标记 SUCCESS，并明确显示“元数据已导入，待补资料”；会议检索状态为 WAITING_CONTENT，不开放问答，也不能核准。
- 仅元数据草稿提供详情页的补充文件上传及补充文本填写入口，无需先发起问答。至少一份有效资料完成解析和索引后，会议变为 AVAILABLE，才允许单场及跨会议问答；人工补充资料始终保留用户来源标识，不冒充腾讯原始内容。
- 超限时展示超限项，允许缩减转写时段及附件范围；确认页显示所选与排除的内容。
- 选择部分转写仍保留腾讯提供的整场摘要；分别记录和展示摘要覆盖整场、转写覆盖所选时段、附件选择范围。
- 有内容的导入须完成确认范围内全部必需获取、解析、索引步骤，才形成可检索草稿会议。任一步失败则整场导入失败，不开放半成品问答；保留失败记录、原因并支持手动重试。仅元数据草稿是明确的无内容路径，不能用于跳过调用、解析或索引失败。
- 来源确实不存在或经验证 API 无法提供的内容不视为调用失败，须明确标示边界；主动排除的内容不算失败。
- 已存在且未删除的成功导入会议阻止重复导入；重复点击和重试不得创建重复会议。
- 首期不提供腾讯侧内容更新。删除草稿后可重新拉取同一腾讯会议；重新导入为新的内部会议记录，不自动恢复旧补充资料。

验收：摘要独有、仅元数据草稿创建与补齐、部分导入、范围内步骤失败、失败重试、重复点击、超限缩减、删除重拉及季度上限均有明确测试。仅元数据草稿同样占名额并阻止重复导入；人工补齐不再次创建会议。

## REQ-MEETING-003 持久化后台处理

导入任务持久化，关闭页面后继续处理；重新进入可查看阶段、进度及错误。服务重启后未完成任务可恢复或重试，避免重复创建会议。阶段包括获取、解析／OCR、索引和完成；进度信息以实际可测阶段为准。

处理失败需显示可操作的错误和手动重试入口。任务的处理中／失败状态与会议的草稿／核准状态分开管理。

## REQ-MEETING-004 草稿、核准与内容修订

- 成功导入默认草稿。用户检查资料完整、可读后核准；无有效资料、解析／索引尚未完成或失败待处理时不能核准。
- 草稿与核准会议均可参与全部问答，但必须满足 AVAILABLE 条件；WAITING_CONTENT、INDEXING、INDEX_FAILED 或 DELETED 均不可问答。引用显示当前使用资料的审核状态。
- 部分导入会议允许核准；核准仅针对所选范围，部分导入标识和排除范围持续保留。
- 摘要和转写允许修订并覆盖保存，不维护全文版本。记录操作人、时间和变更事件。
- 核准会议修订摘要／转写、新增补充资料或删除补充文本后，退回草稿。补充文件删除及删除后重新上传仅允许当前为草稿的会议执行，不能通过删除请求自动将核准会议退回草稿。
- 腾讯原始附件在草稿及核准状态下均只读，禁止单独删除、替换或覆盖；整场草稿会议删除仍执行 REQ-MEETING-005 的留档规则。
- 摘要／转写修订或允许的补充资料删除后，暂停该会议检索，重建索引。成功后恢复；失败保持暂停并支持手动重试。文件纠错采用草稿状态下先删除、再上传的两个操作，不提供直接替换。
- 新上传资料在解析和索引成功前不参与检索。新增补充文件失败仅该文件失败，不额外暂停原有可用内容；若会议已因前一步删除而暂停，则必须先完成该次索引更新，不能因上传失败规则提前恢复问答。

## REQ-MEETING-005 草稿删除与历史留存

- 按当前审核状态判断：当前为草稿即可删除，包括曾核准后退回草稿的会议；当前核准不开放整场删除。
- 删除后会议内容及索引退出新问答，释放季度名额；历史补充资料、问答、待补充问题及引用快照留档。
- 历史引用提示“来源会议已删除”，可查看当时的证据片段；留档内容不能参与新检索。
- 已引用资料发生允许的修订或删除后，对应历史答案标记“来源已变更，可重新回答”。删除后重新上传不覆盖旧记录和旧引用。会议已删除时不得通过重新回答绕过范围不可用规则。
- 重新拉取使用新的内部会议归属，旧对话不自动关联到新会议。

## REQ-DOC-001 会议附件与补充资料

附件分为“腾讯原始附件”和“用户补充文件”两种类型，页面分区显示、分别提供操作，来源类型不可由用户修改。用户直接填写的补充文本独立展示，不混作腾讯原始附件。

腾讯原始附件：由腾讯 API 下载导入，仅允许查看、预览和下载；草稿及核准状态均禁止单独删除、替换、覆盖。用户不能通过上传同名文件修改原始附件。整体删除草稿会议时，原始附件随会议退出检索并按历史规则留档。

用户补充文件：由用户上传，允许新增、查看、预览和下载。纠错采用删除后重新上传，删除和重新上传提交时会议均须处于草稿状态；核准状态拒绝这两类操作，不自动退回草稿以绕过限制。不提供直接替换或覆盖接口。普通新增补充资料仍按既定规则使核准会议退回草稿。

文件唯一性按当前会议内未删除附件的文件内容校验，不以文件名作为唯一判断依据：与腾讯原始附件或已有补充文件内容相同的上传应拒绝，改名不绕过校验；不同会议可各自保存相同文件。失败但尚未删除的上传记录也参加校验，支持对原记录重试，不创建重复记录。删除留档后不占有效文件唯一性，草稿状态允许重新上传并创建新资料记录；历史引用仍指向旧记录。内容摘要（如 SHA-256）可用于判重，并发上传须保证相同内容只产生一条有效补充记录。

文件范围：Word（.docx）、PDF（含扫描 PDF）、图片、Excel、PPT、Markdown、TXT。旧版 Office 格式和具体扩展名清单需在解析器选型后明确，不默认承诺额外格式。

解析要求：

- 扫描 PDF 和图片通过 OCR 提取文字，引用可定位对应页或图片。
- Excel 提取单元格值，引用定位工作表和单元格，不要求公式重算。
- PPT 提取文字及图片中的文字，引用定位幻灯片，不要求图表趋势或流程图关系理解。
- Word、Markdown、TXT 支持文字提取及段落定位；有文本的 PDF 支持页定位。
- 保留原文件及解析状态；错误、加密或不支持的文件提供明确失败原因，不生成虚假内容。
- OCR／解析输出同样作为证据，不能由模型凭自身知识修补后冒充原文。

补充规则：

- 每份文件或文本只归属一场会议，记录提交人和时间，引用标注用户补充资料。
- 跨会议问答中补充资料，必须选择一个目标会议，不自动归属或同时关联多场。
- 腾讯原始附件只读；补充文件仅在当前草稿状态允许删除及重新上传，后端须校验附件来源类型和提交时会议状态，不能仅隐藏页面按钮。
- 补充文本不允许直接修订，只能删除旧文本并新增；新增／删除文本仍执行既定审核状态及索引规则。
- 新增补充文件解析或索引失败时，保留文件与原因，该文件不进入检索，已有可用内容继续参与问答；此规则不解除由删除旧资料造成的检索暂停，也不恢复已删除文件。
- 补充文件合并计入每场附件限制；达到上限时阻止新增并说明原因。
- 仅元数据草稿使用同一补充入口。没有可检索内容时，首份补充资料成功解析并完成索引才开放问答；上传／解析失败保留具体失败原因及重试入口，会议保持不可问答，不把文件处理失败伪装成问答证据不足。

## REQ-QA-001 检索范围选择

- 会议详情提供仅该场会议的问答入口。
- 会议中心支持最多 10 场会议联合问答，用户必须先选择会议。
- 按会议开始时间区间筛选后自动全选匹配会议，用户可取消；超过 10 场时须调整选择后才能开始问答，不静默截取。
- 草稿和核准会议均可选择，历史季度可联合选择；开始问答前所选会议必须全部为 AVAILABLE。时间区间筛选可展示仅元数据草稿，但须提示等待补齐或取消选择，不能跳过它后静默开始问答。
- 每次新建对话默认不选企业知识库；用户可显式添加其可访问的已有 Workspace。不新建独立企业知识库。
- 同一对话固定会议和 Workspace 集合，更换须新建对话；新导入会议不自动加入。
- 已选会议新增资料可在成功入库后参与手动重新回答，不改变对话的会议集合。
- 任一所选会议删除、暂停检索或因最后一份有效资料删除而变为 WAITING_CONTENT，则该对话暂停继续提问和重新回答；显示具体原因。等待恢复或新建对话重新选范围，历史回答仍可查看。

## REQ-QA-002 回答与引用

执行第 2.2 节全部证据规则，并记录回答时间和实际使用的来源。

新导入会议资料：引用显示会议名称、日期、资料名称、来源类型、审核状态及覆盖范围，可点击打开资料并定位到摘要／转写段落、文件页／段落、图片、Excel 工作表与单元格或 PPT 幻灯片。转写接口提供时间戳时保留并展示，不虚构时间戳或说话人。

已有 Workspace：无法精确定位时允许降级，至少显示文档名称、引用片段并可打开原文件，提示无法精确定位。不得仅以 Workspace 名称充当来源。该降级不适用于新导入会议资料的定位要求。

每次回答保存所用引用文字片段快照，不保存全文版本。原文修订后历史引用可查看当时片段，当前原文另行展示并提示已修订；删除后保留历史片段及删除标识。

## REQ-QA-003 待补充、澄清与手动重新回答

- 资料不足时保存问题、缺失信息、对话范围及回答记录，状态为资料待补充，并询问是否补充知识源。
- 用户可向指定会议上传文件或填写文本，索引成功后手动点击重新回答；不自动重答。
- 重新回答保留原答案、引用及待补充原因，新增回答记录；仍缺证据时保持资料待补充。
- 所选会议新增可检索资料后，已有答案提示“有新增资料，可重新回答”；解析／索引失败不触发新增资料提示。
- 引用资料变化则提示“来源已变更，可重新回答”，旧答案不自动改写。
- 待用户澄清与资料待补充分开；服务／模型失败为回答失败／未完成。
- 模型调用中断时保留部分回答并标明回答失败／未完成，不作为有效答案，支持手动重试。

## REQ-CONFIG-001 模型与解析服务

支持企业内网及管理员指定外部服务；问答模型、向量模型、OCR／文档解析服务分别配置，明确各类资料的处理去向。

服务未配置或调用失败时明确提示原因，支持手动重试，不自动切换备用服务，不擅自从内网切换外部服务。外部服务的使用不扩大可检索的知识源范围。

# 6. 页面要求

## 6.1 Meeting Center：`/meetings`

- 企业连接状态和配置入口、腾讯会议列表获取入口。
- 逐场导入入口、范围确认、超限提示、后台任务进度及重试。
- 已导入会议按季度查看，显示草稿／核准、仅摘要／部分导入及检索可用状态；仅元数据会议显示“元数据已导入，待补资料”，可进入详情补资料，不开放问答。
- 按开始时间区间快速多选、取消选择、最多 10 场校验、开启联合问答。
- 不提供自动导入、批量导入或更新已导入腾讯内容的按钮。

## 6.2 Meeting Detail

- Summary：摘要查看、修订、覆盖范围。
- Transcript：全文查看、搜索、修订、所选时段和可用时间戳。
- Documents 分为“腾讯原始附件”和“用户补充文件”两个区，补充文本另设列表；两类附件显示来源和各自数量，同时显示合并限额。
- 腾讯原始附件区仅提供查看、预览和下载；用户补充文件区提供上传及解析状态，草稿状态才提供删除和删除后重新上传，不提供直接替换。重复内容上传提示现有文件并阻止重复入库。
- 仅元数据草稿直接提供文件上传／文本补充入口，不依赖问答入口；显示各资料处理状态，在有效内容入库前禁用问答及核准。
- QA：单场问答、引用定位、历史回答和待补充记录。
- 核准操作、审核状态、草稿删除及历史留档提示。
- 不提供 OA Tasks、Compare 或 Translation 首期菜单。

## 6.3 对话与历史

显示固定的会议与 Workspace 范围；提供引用片段、原文打开及定位、冲突展示、适用条件澄清、待补充问题和重新回答入口。删除或暂停会议导致范围不可用时显示阻断原因，不自动缩减检索范围。

# 7. 逻辑数据模型

以下为需求级实体与关键字段，具体数据库结构在实施时确定；不要求照搬原 PRD 的字段草案。

- Meeting：内部 ID、企业连接 ID、腾讯会议 ID、标题、开始／结束时间、季度、审核状态、检索状态、删除标识、导入范围、覆盖标识、创建及审核信息。去重针对同一连接下当前未删除的腾讯会议，不阻止删除后重拉。
- MeetingContent：会议归属、摘要／转写文本、来源类型、时间段、时间戳／段落定位、内容变更时间。不维护全文历史版本。
- MeetingSource：会议归属、来源类型（腾讯原始附件／用户补充文件／补充文本）、原文件地址、文件内容摘要、提交人和时间、字节数、解析状态、定位信息、索引状态、删除标识。来源类型决定允许的操作；文件唯一性以当前会议有效附件内容判定，删除后重新上传创建新记录，不改写历史引用。
- ImportJob：来源会议、确认范围、阶段、进度、失败原因、重试信息、幂等关联和季度名额预留信息。
- Conversation：固定的会议 ID 集合和 Workspace ID 集合、创建信息、当前范围是否可用。
- Question / Answer：问题、澄清或缺失信息、回答状态、回答时间、重答关联、历史回答、所用来源及变更／新增资料提示。
- CitationSnapshot：回答归属、会议／Workspace 来源、文档标识、定位信息、当时引用文字、当时审核状态与覆盖范围、来源后续变更或删除标识。
- AuditEvent：连接配置、导入／重试、核准、修订、补充、删除及重新回答等操作的主体、时间与结果，不记录明文密钥。

# 8. 状态模型

状态相互独立，不使用原文的 COMPLETED → FAILED 线性模型。

## 8.1 导入任务

    CREATED → PROCESSING → SUCCESS
                         → FAILED → 手动重试 → PROCESSING

SUCCESS 表示确认范围内全部必需导入步骤完成。含有效内容的会议在解析和索引完成后为 AVAILABLE；仅元数据路径表示元数据已持久化，会议为 DRAFT + WAITING_CONTENT，不代表问答就绪。范围内处理失败仍为 FAILED，不得转为仅元数据成功以绕过失败规则；人工补齐是独立的资料处理任务，不重复导入会议。

## 8.2 内容审核

    成功导入 → DRAFT → 用户审核确认 → APPROVED
                ↑                        │
                └── 修订／补充资料变更 ──┘

当前 DRAFT 可整场删除；APPROVED 不可直接整场删除。仅元数据草稿须先取得有效内容、完成解析和索引，再执行审核核准。腾讯原始附件始终只读；补充文件仅在 DRAFT 下可删除及重新上传，APPROVED 下不能通过删除自动降为 DRAFT。部分导入标识独立于审核状态。

## 8.3 检索状态

WAITING_CONTENT、AVAILABLE、INDEXING、INDEX_FAILED、DELETED。

- WAITING_CONTENT：仅有元数据或无有效可检索内容；可在详情补资料，不可问答／核准。与问答层面的 AWAITING_SOURCES 区分，后者是已有可检索资料仍不足以回答某个问题。
- 无内容会议首次补资料时显示资料处理进度；至少一份有效资料完成解析和索引，且不存在未完成的删除清理／重建任务后，才进入 AVAILABLE。失败保留错误，会议不开放问答。
- 摘要／转写修订或允许的补充资料删除时进入 INDEXING 并暂停问答；失败进入 INDEX_FAILED 并保持不可用，重试成功才恢复。删除最后一份有效资料后，旧索引清理成功则进入 WAITING_CONTENT，而非 AVAILABLE；清理失败仍为 INDEX_FAILED。
- 新增补充文件失败不使原有可用内容失效；删除后重新上传视为独立新增，不覆盖删除步骤的 INDEXING／INDEX_FAILED 状态。DELETED 表示会议已删除并退出检索。

## 8.4 问答状态

PROCESSING、ANSWERED、AWAITING_CLARIFICATION、AWAITING_SOURCES、FAILED_INCOMPLETE。

来源变更、新增资料及范围不可用作为额外提示或对话可用性标识，不覆盖历史回答本身。

# 9. 失败语义与一致性

- 初次导入确认范围内的获取／解析／索引失败：整场失败，保留任务记录，支持手动重试，无可问答半成品。
- 来源不存在、能力不可获取和调用失败必须分别处理，不能混淆。
- 仅元数据草稿不是失败任务：创建后占季度名额、阻止重复导入，可补资料或删除重拉；未补齐有效内容前不开放问答。实际调用或内容处理失败不得降级为此路径。
- 新增补充文件失败：保留原文件，仅该文件失败，已有可用内容继续可用；不得解除因删除旧资料造成的暂停，不得恢复被删除的旧资料。
- 摘要／转写修订或允许的补充资料删除引起索引更新失败：会议保持暂停检索；包含该会议的对话暂停，手动重试成功后恢复。
- 原始附件删除／替换请求、核准会议的补充文件删除／重新上传请求必须拒绝，且不得改变审核状态。重复上传不得新增文件、索引或消耗重复名额；并发请求遵守同一唯一性规则。
- 删除确认后，原会议及留档资料不能再成为新回答证据，包括正在处理请求的后续结果；保留历史引用不等于保留检索资格。
- 超过季度名额、单次选会数或附件限制时提供明确提示；允许源会议导入范围缩减，不静默丢弃。
- 服务未配置／异常不自动切换，不伪装为资料不足；失败部分回答仅作未完成记录。

# 10. 安全与审计

沿用 AnythingLLM 既有登录和 Workspace 可访问范围。会议专属权限规则及接口过滤后续增加，不在本轮展开。

腾讯会议凭证加密存储，不明文展示；配置和调用日志不得泄露密钥。模型、向量和解析服务由管理员配置。关键操作留存审计事件。历史留档必须与有效检索来源区分，删除资料不得被再次检索泄露到新答案。

无高等级安全问题仍为发布条件；OA 密钥相关要求随 OA 功能延期。

# 11. 验收场景

- API 真实连接和会议列表：以企业账户实测，列出摘要、转写、附件能力的验证结论及人工补齐路径。
- 导入：摘要独有、完整导入、部分范围、超限缩减、分页、产物延迟、失败重试、去重、删除重拉、季度限额并发控制；仅元数据草稿占名额并阻止重复导入、详情补资料前不可问答／核准、补齐且索引成功后可用、失败不误报就绪。
- 后台任务：关闭页面继续、重进查看、服务重启恢复／重试、不重复创建。
- 审核与修订：默认草稿、核准、部分导入核准、修订／补充退回草稿、索引更新暂停及恢复。
- 文件：两种附件分区及来源标识；腾讯原始附件查看／下载可用、删除／替换被拒绝；草稿补充文件删除重传、核准状态拒绝；内容相同但改名、重复点击、并发上传、失败文件重试、删除后重新上传及跨会议独立保存的唯一性校验；支持格式、OCR、Excel／PPT 定位、合并限额及解析失败。
- 检索：单场、跨季度最多 10 场、时间筛选自动全选后调整、显式 Workspace、固定范围及范围不可用阻断。
- 回答：有据结论、建议与决定区分、冲突并列、适用条件先澄清、证据不足提示补充、不用模型知识补事实。
- 来源：新会议资料精确定位、已有 Workspace 降级提示、引用片段快照、修改／删除后仍可查看旧证据但不用于新检索。
- 补充与重答：文件／文本归属单场、文本删除再新增；补充文件删除引发暂停与重新上传失败的状态组合、失败不恢复旧文件；最后一份有效资料删除后回到 WAITING_CONTENT；手动重新回答保留历史及资料变化提示。
- 调用异常：未完成回答保留并标记、手动重试、不自动切换服务。

# 12. 验收材料与质量指标

采用构造样例和脱敏真实供应链仓库资料：构造样例覆盖异常和边界，真实资料验证第 2.1 节业务问题。项目组依据资料整理并确认标准答案，每题附依据，区分决定、建议、冲突和缺失证据，不强制业务负责人参与。

## 12.1 必须零出现的错误

验收题集中以下错误必须零出现：无来源补充事实、伪造引用、用已删除内容回答新问题、资料不足却给出确定结论。此标准限定于验收题集，不表示对线上所有回答作绝对无误承诺。

## 12.2 先实测再定门槛

检索遗漏、回答不完整、OCR 识别错误、引用定位偏差先测量，再确定通过率门槛。约 10 人并发下记录开始显示及完整回答耗时、失败率，发布前确定性能门槛。不得仅凭“已经实测”通过验收。

## 12.3 证据记录

每个需求提供适用的 API 测试记录、UI 截图、数据库记录和日志。区分模拟测试与真实腾讯 API 测试；保留部署信息、题集、预期答案、实际答案、引用及质量性能结果，记录未通过项及复验结果。

# 13. 发布条件

- 首期必需功能及异常场景通过验收。
- 腾讯会议真实 API 连接和会议列表通过；其他内容能力取得明确结论，不可获取项的人工补齐路径通过验收。
- 第 12.1 节错误在验收题集中零出现。
- 质量通过率及响应性能门槛已根据实测确定，并满足门槛。
- Linux 全新部署通过后台任务、解析／OCR、预览定位、索引、模型调用和故障恢复验证。
- 无高等级安全问题，凭证保护及关键操作审计通过。
- 不要求旧实例迁移验证，不以延期的比较、翻译、OA 或会议权限功能阻止本期发布。

# 14. Definition of Done

1. 企业管理员可配置真实腾讯会议 API，用户可逐场导入。
2. 后台任务、范围限制、失败重试及去重满足规则。
3. 摘要、转写、附件、补充文本可管理，草稿／核准／删除及修订生效。
4. 单场、多场及显式 Workspace 联合问答可用，固定范围和不可用阻断正确。
5. 回答证据规则、原文定位、引用快照及历史记录通过验收。
