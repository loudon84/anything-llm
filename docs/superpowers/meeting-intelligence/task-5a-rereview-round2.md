## Remaining finding F4 — resolved

**Separate import preparation batches:** `prepareImport` now preserves the profile identity with each prepared source (`server/modules/meetings/sources.js:951`). `commitImport` flattens every prepared source's chunks into one shared validation call and rejects a source prepared under a different profile before it creates source/chunk rows or copies originals (`sources.js:1048-1063`). The shared check rejects missing/mismatched profiles, non-array/empty/nonfinite/zero vectors, and inconsistent dimensions across the entire set (`server/modules/meetings/indexer.js:167-205`). Thus the prior summary-2D/transcript-3D trigger cannot commit the meeting as AVAILABLE. The new real-Prisma source regression also checks that the outer transaction rolls back the meeting state and leaves no source/chunk rows, and separately rejects a mismatched prepared profile.

**Supplemental current-index publication:** source processing now obtains current-generation chunks and the active successful source IDs inside its owning publication transaction. It validates eligible existing chunks together with all candidate chunks, excluding only the candidate source's replaced old chunks (`sources.js:731-760`). This occurs before the availability update and before the transaction returns. Candidate chunk writes and candidate source SUCCESS are earlier operations in that same transaction; a validation exception rolls them back together. The existing lease, exact source revision, generation, and deletion guards still precede these writes (`sources.js:691-704`), so validation does not weaken stale-job protection.

**Source-only failure preservation:** after rollback, the existing failure transaction records the candidate as FAILED and audits that controlled failure (`sources.js:800-883`). For an already AVAILABLE meeting, it leaves the prior availability and chunks intact. The new incompatible-supplement regression verifies one prior chunk remains, the candidate is FAILED, and actual indexer search still returns the prior decision. The failure does not silently become missing evidence or expose partially committed candidate content.

**Reindex/profile contract:** reindex uses the same shared validator on its complete prepared set before publication (`indexer.js:382-386`). It still uses generation/source-set/lease checks for publication. `validateIndex` is explicitly exposed on the indexer (`indexer.js:495`) and is now required by the injected source-service indexer contract. Object envelopes retain their mandatory profile identity; the intentional legacy array fixture behavior remains mapped to the default profile. Import profile checking prevents relabeling a stale prepared source with the current profile at commit time.
