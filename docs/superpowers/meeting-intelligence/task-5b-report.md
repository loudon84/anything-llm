The `202` status applies to import, file upload, and reindex because those operations return queued durable work; other successful routes use `200`. The response object inside each envelope is the corresponding Task 2/3/4 service record. For questions, the service can return a completed answer, an `AWAITING_SOURCES` record, or a controlled failure record; HTTP itself remains the normal JSON success path when the QA service successfully persisted that answer state. Unexpected 5xx text is hidden behind `Meeting request failed`; useful safe domain errors retain their status and code.

## Runtime/provider integration

- `createMeetingRuntime` is built around injected Prisma and adapter factories. Every import, parse, reindex, question, and explicit rebuild operation captures the then-current embedder/model/profile and current decrypted OCR/Tencent config. It does not keep a boot-time parser or indexer after admin settings change. Job handlers are registered for `IMPORT`, `PARSE_SOURCE`, and `REINDEX`; the durable runner starts with the API server and stops on server shutdown.
- `bootHTTP` now returns the actual listener instance (matching `bootSSL`), and `attachMeetingRuntime` binds runner start/stop to that listener's `listening`/`close` events. Regression coverage exercises both HTTP and HTTPS listener lifecycle events; the `bootHTTP` regression first failed because the previous return value was `server: null`.
- The profile ID used for an operation is `${EMBEDDING_ENGINE}:${embedder.model}`. The runtime wraps `embedChunks` and `embedTextInput` as indexer `embedDocuments` and `embedQuery` and sanitizes embedding errors. Reindex is an explicit queued action.
- Tencent remote list/manifest/import calls use the private saved connection config through the existing Tencent adapter; the API returns the public manifest only. No arbitrary URL proxy was added.
- QA selects the existing provider router for the authenticated user with a synthetic meeting context and an explicitly empty prior Workspace chat history. The actual grounding policy is sent as a system message. There is no fallback provider. Streaming-capable providers use their existing stream handler behind an EventEmitter-compatible bounded event sink; abort/provider error with emitted partial text becomes `FAILED_INCOMPLETE`. A completion-only provider cannot expose bytes it did not return. Provider failures are controlled, and configured secret values/raw provider bodies are not returned to clients.
- Workspace retrieval calls the configured vector provider with the selected Workspace namespace and current operation embedder. The real provider projection is flattened chunk metadata plus text. The adapter takes the provider's vector/chunk `id` (or explicit vectorId), maps it through `document_vectors.vectorId` to the actual `docId`, then requires the exact current `workspace_documents` membership and authenticated Workspace lookup. It does not infer identity from filename. Multiple vectors from one document each retain a distinct `vector:<provider-vector-id>` evidence ID and share the actual document ID/revision. Location metadata is restricted to the supported paragraph/page/image/cell/slide/transcript locator shape; other provider metadata is not copied into evidence.
- Workspace revision is SHA-256 over the current document's `lastUpdatedAt`, stored metadata, and sorted actual vector IDs. The Workspace original link appears only when the actual flat `workspaceOriginalId` resolves for that exact workspace/document binding. The file endpoint separately rechecks authenticated Workspace access and live document membership. Its file stream is contained under `storage/workspace-originals`; meeting source streams remain contained under `storage/meetings`.
- Critical state changes use the transaction-aware audit callback from Task 5a. Admin config GET returns redacted settings; employee GET deliberately strips identifiers, service URLs, and credential hints. All routes use `validatedRequest`; config PUT adds the existing admin role check. Single-user mode follows the application's existing admin-equivalent behavior.

## Self-review and known limits

- Tencent original attachments have no delete/replace operation. Supplemental source deletion uses the service's draft/approval and source-type rules; retained historical source reads are read-only.
- The Workspace vector mapping depends on providers returning an actual stored vector ID in their flattened source projection; the tested fixture matches the repository provider contract. Provider-specific production behavior has not been tested against live vector stores.
- Revision hashes incorporate current document timestamp/metadata plus the actual vector identity set. If an external vector backend mutates content in place while preserving both its vector IDs and the Workspace row timestamp/metadata, that backend gives this adapter no detectable content revision signal; such a provider must ensure re-embedding changes IDs or advance the Workspace document revision as part of its update path.
- Locators are preserved only when providers expose the agreed locator fields. The adapter intentionally does not invent page, paragraph, or source links.
- Prompt instructions and citation/quote validation do not prove semantic entailment. Live model quality, live API/OCR behavior, production performance, and Linux fresh deployment were not claimed as verified.
