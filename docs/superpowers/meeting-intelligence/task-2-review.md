# Task 2 review

**Spec compliance: changes required. Quality: changes required.** The focused tests reported in the implementation report passed, but they do not exercise the incomplete-content cases below. This is a read-only review; no tests were rerun. Official documentation establishes endpoint behavior, not this tenant's grants or artifact availability; live credential verification remains release work.

1. **P1 — Structured transcripts are truncated after the first page.** `server/modules/meetings/tencent.js:325-350` requests transcript details once per recording and never follows the documented `more`/`pid` pagination. A recording with more than one page is committed as available with only its first paragraphs, violating the full selected import scope. Follow continuation until `more` is false, reject a stalled/repeated cursor, and test a two-page recording.

2. **P1 — Selected artifacts can disappear silently between preflight and import.** `server/modules/meetings/importer.js:373-427` filters the returned artifact list by `scope.attachmentIds` but never checks that every requested ID was returned. If a selected artifact is missing or its short-lived URL disappears, the job can succeed with the remaining content, violating all-or-nothing scope. Compare requested IDs with discovered/downloaded IDs before `prepareImport`; fail the job on any missing selection. Add a preflight-to-worker change test.

3. **P1 — A later recording can erase earlier summary content.** `server/modules/meetings/tencent.js:369-385` assigns `result.summary` for each file, including `null` when the later file has no minutes. For a meeting whose first recording has minutes and second does not, the importer loses the first summary and may create a metadata-only meeting. Accumulate minutes with recording provenance, and compute capability state across all recordings instead of letting the last one overwrite it (`:350-365` has the same state problem for transcripts). Test mixed-content recordings.

4. **P1 — Successful but malformed API responses are classified as source absence.** `server/modules/meetings/tencent.js:225-227, 329-355` treats missing `record_meetings`, `minutes`, or `paragraphs` fields as empty arrays. An HTTP 200 response with a changed or malformed body can therefore become a metadata-only success through `server/modules/meetings/importer.js:428-477`, although parse/runtime failure must fail the import. Validate each documented response envelope; reserve `absent` for confirmed empty content and documented no-content codes. Test malformed 200 bodies separately from valid empty lists.

5. **P2 — Empty artifact discovery is reported as supported content.** `server/modules/meetings/tencent.js:387-415` leaves attachment capability `supported` when detail calls return no downloadable artifact URL. If all other sources are absent, `server/modules/meetings/importer.js:429-437` fails the job rather than creating a `WAITING_CONTENT` draft with a manual supplement path. Mark confirmed empty artifacts `absent` and preserve the reason; test an empty detail response.

6. **P2 — Download timeout stops before the body is read.** `server/modules/meetings/tencent.js:137,160,512-551` clears the request timeout when returning the response, then streams the artifact without a deadline. A stalled Tencent download can hold a leased job indefinitely. Keep an abort/deadline active through the complete stream and test a stalled body reader.

The canonical signing construction and Unix-seconds conversion match the supplied official research. The review found no concrete signing or date conversion defect. The download host check is applied to the initial URL; if redirects are permitted, ensure the final response URL also stays within the allowed Tencent domains before consuming it.
