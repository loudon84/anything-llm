# Task 7 integration and release evidence

## Integration changes

- The PDF parser now inspects the actual bundled PDF.js operator list for image paint operations. It sends image-containing pages to the configured parser even when native text is present on that same page, combines both located results, and still leaves pure-text PDFs local. A generated `pdf-lib` test PDF includes a native header and image XObject on one page; the controlled parser returns the scanned body at page 1. Existing tests keep the OCR failure, invalid locator, and pure-text behavior covered.
- The source-publication transaction now rejects a renamed reupload of a deleted supplemental file when the meeting is APPROVED. The historical `contentHash` guard is scoped to that meeting and only applies to `SUPPLEMENT_FILE`; a genuinely new approved file still downgrades to DRAFT. Real Prisma integration verifies rejection leaves approval, generation, retrieval status, active sources, archived bytes, and quota state intact; a DRAFT reupload receives a new source ID, active same-meeting duplicates fail, and identical content on another meeting is allowed.
- The attachment limit now counts bytes and file slots only for active Tencent original attachments and user supplemental files. Supplemental text does not consume either quota. The integration boundary test creates synthetic Prisma metadata for 499,999,999 and 500,000,000-byte files without allocating large buffers: text is accepted at the full file limit, a one-byte file is rejected above it, existing text bytes do not block a file at the exact limit, and that accepted file is parsed through the durable source job.
- Conversation history now returns a top-level `answers` array alongside the `conversation` metadata. The real `qa.history()` contract is `{ conversation, answers }`; wrapping that object in another `answers` field caused the page to call `.slice()` on an object. The client now rejects malformed history envelopes explicitly instead of silently treating them as an empty history.
- The meeting detail page uses the same attachment-only accounting, accepts text without adding a product-specific text-size limit, and explains the combined file quota accurately. Source type and locator labels are shown in Chinese. A source opened directly from details is labeled as the current source and no longer claims that an answer snapshot exists. The center's blocker copy now says “资料就绪” rather than exposing `AVAILABLE`.
- Text and HTML/XML/SVG/script-like sources display as ordinary escaped React text, not rendered markup. Only PDF and common raster image MIME types/extensions are embedded, in an iframe sandboxed without script permission; unsupported/unknown binaries get a download-only message. The original blob remains downloadable. Frontend regressions check the type allowlist, text escaping, and that the iframe sandbox never includes `allow-scripts`.
